# zont-auth Specification

## Purpose
Авторизация в облаке ZONT: получение токена доступа по логину и паролю, безопасное
хранение только токена и обработка его отзыва.

## Requirements

### Requirement: Получение токена по логину и паролю
Приложение SHALL получать токен доступа запросом `POST /api/widget/v3/authtokens`
с HTTP Basic-аутентификацией (логин:пароль) и телом `{"client_name": "ZONT Пульт (Android)"}`.
Каждый запрос к API MUST содержать заголовок `X-ZONT-Client` со значением логина пользователя.

#### Scenario: Успешный вход
- **WHEN** пользователь вводит верные логин и пароль и нажимает «Войти»
- **THEN** приложение получает `token` из ответа
- **AND** сохраняет логин и токен
- **AND** очищает поле пароля
- **AND** загружает список устройств

#### Scenario: Неверный логин или пароль
- **WHEN** сервер отвечает HTTP 401
- **THEN** приложение показывает ошибку «Неверный логин или пароль» и не сохраняет токен

#### Scenario: Пустые поля
- **WHEN** логин или пароль не заполнены и пользователь нажимает «Войти»
- **THEN** приложение показывает «Введите логин и пароль» без обращения к серверу

### Requirement: Пароль не хранится
Приложение MUST NOT сохранять пароль пользователя ни в каком виде; все последующие запросы
SHALL аутентифицироваться заголовком `X-ZONT-Token`.

#### Scenario: Повторный запуск
- **WHEN** приложение перезапускается после успешного входа
- **THEN** оно работает с сохранённым токеном, пароль не требуется

### Requirement: Отзыв токена
При ответе API с HTTP 401 или 403 приложение SHALL считать токен недействительным,
удалить его и предложить повторный вход.

#### Scenario: Токен отозван
- **WHEN** запрос состояния или команды возвращает 401/403
- **THEN** токен удаляется
- **AND** показывается сообщение «Требуется повторный вход в ZONT»
- **AND** открывается окно настроек с формой входа

### Requirement: Выход из аккаунта
Окно настроек SHALL позволять выйти из аккаунта, удаляя токен.

#### Scenario: Выход
- **WHEN** пользователь нажимает «Выйти»
- **THEN** токен удаляется, снова показывается форма входа, список устройств скрывается

### Requirement: Удобный ввод учётных данных
Поля логина и пароля SHALL поддерживать вставку из буфера обмена как системным меню,
так и отдельными кнопками «Вставить»; пароль SHALL можно показать флажком «Показать пароль».

#### Scenario: Вставка из буфера кнопкой
- **WHEN** пользователь нажимает «Вставить» рядом с полем
- **THEN** текст из буфера обмена (без пробелов по краям) вставляется в позицию курсора этого поля

#### Scenario: Буфер пуст
- **WHEN** в буфере обмена нет текста и пользователь нажимает «Вставить»
- **THEN** показывается сообщение «Буфер обмена пуст» (или «В буфере обмена нет текста»)

#### Scenario: Показ пароля
- **WHEN** пользователь отмечает «Показать пароль»
- **THEN** пароль отображается открытым текстом, позиция курсора сохраняется
